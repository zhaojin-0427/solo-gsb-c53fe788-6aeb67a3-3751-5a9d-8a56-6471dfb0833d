# 无线话筒频点协调台

面向演出场景的无线话筒频率协调 Web 应用。录入 2～8 支话筒各自的候选频点、
现用频点与锁定标志、禁用闭区间及协调参数后，由 **OR-Tools CP-SAT** 在指定
时限内求解决策：哪些设备分配哪个候选频点（允许未分配），并按规定的字典序
目标选出最优方案；界面以表格与频谱视图展示结果，方案可保存后随时重新打开。

- 后端：Python 3.11 · FastAPI · SQLite（标准库 `sqlite3`）· OR-Tools CP-SAT
- 前端：原生 HTML / CSS / JavaScript（无构建步骤、无前端框架）
- 部署：Docker Compose 一键启动，数据持久化到命名卷

## 一、一键启动（推荐）

```bash
docker compose up -d --build
```

启动后访问：

| 入口 | 地址 |
| --- | --- |
| 应用界面 | <http://localhost:8000/> |
| FastAPI 交互文档（Swagger UI） | <http://localhost:8000/docs> |
| OpenAPI 描述 | <http://localhost:8000/openapi.json> |

停止 / 查看日志 / 重新构建：

```bash
docker compose logs -f
docker compose down            # 停止（保留数据卷）
docker compose down -v         # 停止并删除方案数据
```

SQLite 数据库保存在容器内 `/data/plans.db`，由 Compose 命名卷
`mic_data` 持久化，容器重建后方案与结果仍在。

## 二、本地直接运行（不使用 Docker）

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

数据库路径可用环境变量覆盖（默认 `/data/plans.db`，本地建议改到当前目录）：

```bash
DB_PATH=./plans.db uvicorn app.main:app --reload
```

访问地址同样为 <http://localhost:8000/>。

## 三、使用说明

1. 顶部填写**演出方案名称**，录入 2～8 支话筒：
   - **候选频点**：1～12 个互异正整数（kHz），空格、逗号等分隔均可；
   - **现用频点**：可选；若填写必须是该设备候选频点之一；
   - **锁定**：勾选后必须填写现用频点，求解时该设备强制保留现用频点。
2. 设置协调参数：
   - **最小频差 d**：正整数 kHz，任意两台已分配设备的频差绝对值 `≥ d`；
   - **互调容差 g**：非负整数 kHz，任意互异三台 i,j,k 须满足
     `|2fᵢ − fⱼ − fₖ| > g`（覆盖每个频点作为互调中心的三种位置）；
   - **求解时限**：正整数秒，传给 CP-SAT 的墙上时间限制；
   - 可添加若干**禁用闭区间 [lo, hi]**，区间内频点不得分配。
3. 点击 **协调求解**。
   - 若锁定设备的固定频点彼此已冲突（落入禁用区间 / 频差不足 d /
     三支违反互调容差），不启动求解，直接列出**冲突设备与规则明细**；
   - 否则允许未分配，按下述三级**字典序目标**选解：
     1. 最大化已分配台数；
     2. 在台数相同的方案中，最小化已分配设备的现用频点**变更台数**
        （无现用频点的设备不计变更；锁定设备恒不变更）；
     3. 仍并列时，按设备 ID 升序取**频点序列**字典序最小，未分配视为
        大于所有候选频点。
4. 结果区显示状态徽章（**已证最优** / **找到可行解（未证最优）** /
   无可行解 / 锁定冲突等）、已分配与变更台数、求解耗时；时限内未证最优时
   照常展示当前**可行解并明确标注“未证最优”**。
5. **频谱视图**实时绘制：候选频点、现用频点、已分配频点及其 ±d 保护带、
   禁用闭区间。
6. 点击**保存方案**持久化（求解保存方案时结果也一并保存）；通过顶部下拉框
   可重新打开任意已保存方案（连同上次结果），也可删除方案。未保存时仍可
   直接求解（结果仅在当前页面中展示）。

## 四、HTTP API 摘要

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/plans` | 方案列表（含最近结果） |
| `POST` | `/api/plans` | 新建方案（请求体即方案 JSON） |
| `GET` | `/api/plans/{id}` | 打开方案 |
| `PUT` | `/api/plans/{id}` | 更新方案 |
| `DELETE` | `/api/plans/{id}` | 删除方案 |
| `POST` | `/api/plans/{id}/solve` | 求解已保存方案并持久化结果 |
| `POST` | `/api/solve` | 对请求体中的方案直接求解（不入库） |

方案 JSON 示例：

```json
{
  "name": "示例演出方案",
  "devices": [
    {"name": "主唱麦", "candidates": [600000, 600400, 600800],
     "current": 600000, "locked": true},
    {"name": "和声麦", "candidates": [600200, 600600, 601000],
     "current": 600600, "locked": false}
  ],
  "forbidden": [{"lo": 601000, "hi": 601100}],
  "settings": {"min_gap": 300, "imd_tolerance": 200, "time_limit": 10}
}
```

入参非法（候选非正整数/重复/数量越界、现用频点不在候选中、锁定设备无现用
频点、区间端点非法等）时返回 `422` 并附字段级错误信息。

## 五、求解模型要点

- 每支设备一个“频点序号”变量（升序候选下标，追加一个“未分配”末位），
  通过指示变量映射到实际 kHz 频点；未分配取大于所有候选频点的哨兵值。
- 两两频差、三支互调约束均用“两支/三支均已分配”作为条件（半具体化），
  因此未分配设备不会触发任何射频约束。
- 三级字典序目标被精确编码为单个加权和：
  台数项与变更项的权重分别严格压过所有低优先级项的最大可能差值，
  频点序列以 13 为底做位置加权（每设备最多 12 个候选）。
